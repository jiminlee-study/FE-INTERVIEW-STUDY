# Q77. 브라우저 캐싱 전략을 설명할 수 있나요?

### 캐싱이란?

- **캐싱**: 비용이 많이 드는 작업을 매번 반복하지 않기 위해 **결과를 미리 저장해 두고 재사용하는 기술**
    - 웹 환경에서 가장 큰 비용이 큰 작업 → **네트워크 요청**
    - 캐싱은 불필요한 네트워크 요청을 줄여 서버 부담을 덜고 사용자에게는 훨씬 빠른 경험을 제공함.
- 캐싱 과정
    1. [사용자] → [브라우저] **브라우저 접속**
        - 사용자가 웹 사이트에 처음 방문 → 브라우저는 아무런 정보가 없는 백지 상태.
    2. [브라우저] → [서버] **이미지 파일 요청**
        - 이때 브라우저가 서버에 이미지 파일 요청
    3. [서버] → [브라우저] **이미지 파일과 헤더 정보**
        - 서버가 요청을 받아 이미지 파일을 전달하면서 함께 **HTTP 헤더**라는 일종의 설명서를 보냄.
        - 이 설명서에 캐싱 전략을 위한 지시 사항인 **Cache-Control**과 **Etag** 같은 정보가 담겨 있음.
            
            ```json
            HTTP/1.1 200 OK
            Cache-Control: public, max-age=31536000
            ETag: "v1-aBcDeFg12345"
            Content-Type: image/png
            ```
            
    4. [브라우저] → [메모리 또는 디스크] **이미지 파일과 헤더 저장**
- 이렇게 한 번 저장된 데이터는 이후 **동일한 요청이 발생**했을 때 다시 서버에 요청하지 않고 **캐시에 있는 내용을 바로 사용**한다.

### Cache-Control이란?

- **Cache-Control:** 브라우저에 이 파일은 **앞으로 얼마 동안 유효**하니 그 동안은 **서버에 다시 물어보지 말고 그대로 사용**하라고 전달하는 역할.
- 파일 유형에 따른 캐싱 전략
    - **절대 변하지 않는 파일**
        - 로고 이미지, 폰트 파일, 특정 버전의 라이브러리 파일처럼 한번 배포되면 내용이 바뀌지 않는 파일.
        - **Cache-Control을 길게 설정**하여 브라우저와 CDN 같은 캐시 서버가 해당 파일을 오랫동안 저장해두고 재사용 가능.
            
            ```json
            Cache-Control: public, max-age=31536000
            ```
            
            - `public`: 브라우저뿐만 아니라 CDN 같은 모든 캐시 서버에 저장 가능
                
                → `public` 옵션이 없거나 `private`으로 설정되면 CDN은 해당 파일을 캐싱하지 못하고 사용자 브라우저에서만 저장됨.
                
            - `max-age=31536000`: 이 파일이 유효한 기간. 31,536,000초 이므로 1년이다.
        - 사용자가 다시 웹 사이트를 방문했을 때: 브라우저가 이미지를 요청하기 위해 네트워크를 전혀 사용하지 않고 **이미 저장해 둔 캐시 저장소에서 즉시 파일을 꺼내 씀.**
    - **내용은 바뀌지만 확인은 필요한 파일**
        - 대표적으로 웹 사이트의 메인 index.html
            
            → 수시로 바뀔 수 있지만 **항상 최신 상태를 유지**해야 함.
            
            ```json
            Cache-Control: no-cache
            ```
            
            - no-cache: 이 옵션은 파일을 **캐시에 저장**해 두되, **사용하기 전에 서버에 이 파일이 아직 유효한 버전인지 확인**하라는 의미.
                
                → 캐시하지 말라는 뜻 아님
                
            

### ETag란?

- **ETag**: 파일의 **특정 버전을 식별**하기 위한 **고유한 버전 태그**
    - 파일 내용이 1byte라도 변경되면 서버는 완전히 새로운 ETag를 생성함.
    - 서버와 브라우저는 해당 파일이 이전에 받았던 것과 같은지 아니면 바뀌었는지 정확하게 판단 가능.
- Cache-Control: no-cache로 설정된 파일을 브라우저가 다시 사용할 때의 과정
    
    > 웹 사이트에 처음 접속했을 때
    > 
    1. [브라우저] → [서버] **파일 요청**
        - 사용자가 웹 사이트에 처음 접속. 브라우저가 서버에 파일을 요청한다.
    2. [서버] → [브라우저] **파일과 Cache-Control, Etag값 응답**
        - 서버가 파일과 함께 **Cache-Control과 Etag값을 응답으로 보냄.**
    3. [브라우저] → [브라우저 캐시] **브라우저 캐시에 값 저장**
        - 브라우저가 이 **파일을 화면에 표시**한 뒤 **ETag 정보와 함께 캐시에 저장**해둠.
    
    > 웹 사이트에 다시 접속했을 때
    > 
    1. [브라우저] → [브라우저 캐시] **캐시 유무 확인**
        - 사용자가 다시 웹 사이트를 방문하면 **브라우저는 먼저 캐시에 해당 파일이 있는지 확인.**
        - Cache-control이 **no-cache**로 설정되어 있다면 브라우저는 이 파일을 바로 사용하지 않고 **서버에 최신 버전인지 확인해야 한다**는 사실을 인식함.
    2. [브라우저] → [서버] **파일 버전 확인 요청**
        - 브라우저가 이전에 저장해 둔 ETag 값을 함께 보내는 조건부 요청을 서버로 전송.
        - 지난번에 받은 파일이 아직도 같은 버전인지를 묻는다.
            
            → 이 요청에는 If-None-Match 헤더가 사용됨.
            
    3. [서버] → [브라우저] **서버의 판단과 응답**
        - 서버가 현재 파일의 Etag와 브라우저가 보낸 Etag를 비교한다.
        - Etag가 같다면 서버는 파일 본문 없이 304 Not Modified 응답을 보냄.
            
            → 브라우저는 캐시에 저장된 파일을 그대로 사용.
            
        - Etag가 다르다면 서버는 새로운 파일과 함께 200 OK 응답을 보냄.
            
            → 브라우저는 **캐시를 최신 파일로 갱신.**
            

### 결론

- 절대 변하지 않을 자원(로고, 폰트, 버전 라이브러리) → `Cache-Control: max-age`를 길게 설정하여 불필요한 네트워크 요청을 원천 차단한다.
- 자주 변할 수 있는 자원(HTML, API 응답) → `Cache-Control: no-cache`와 ETag를 함께 사용하여 파일이 변경되지 않았을 경우 데이터 다운로드를 생략한다.

### 모의 면접

1. Cache-control: max-age와 Cache-Control: no-cache의 차이는 무엇이며 각각 어떤 자원에 적용하는 것이 적절한가요?
    
    > **둘 다 Cache-control 헤더의 지시어**로, max-age는 이 파일이 유효한 기간을 정의하며 로고, 폰트, 버전된 라이브러리 등 절대 변하지 않을 자원에 사용하는 것이 적절합니다.
    no-cache는 파일은 저장해두되 사용 전 서버에 이 파일이 유효한 버전을 먼저 확인하라는 뜻이며 자주 변할 수 있지만 항상 최신 상태를 확인해야 하는 자원에 사용하는 것이 적절합니다.
    > 
2. 브라우저가 ETag와 If-None-Match 헤더를 이용해 파일 변경 여부를 어떻게 확인하나요?
    
    > 브라우저가 If-None-Match 헤더를 사용해 서버에 ETag 값을 보내 지난번에 받은 파일이 아직 같은 버전인지를 확인 받습니다. 이때 Etag가 같다면 서버는 파일 본문 없이 304 Not Modified를 보내고, Etag가 다르다면 새로운 파일과 함께 200 OK 응답을 보냅니다. 이로써 파일 변경 여부를 확인할 수 있습니다.
    >
