# Q08. data-* 속성을 설명할 수 있나요?

- HTML 태그에는 id, class, src처럼 저마다 정해진 역할을 가진 속성만 사용해야 함.
- 만약 my-custom-info=”값”처럼 임의로 속성에 만들면 HTML 표준에서 어긋남.
- 실제 개발할 때에는 사용자 ID처럼 각 요소에 고유 데이터를 저장하고 js로 읽고 조작해야 하는 경우 많음.
    
    → 이를 표준 방식으로 해결하는 것이 data-* 속성.
    

### data-* 속성의 의미

- data-* 속성: **자바스크립트에서 사용할 데이터를 HTML 요소에 저장하는 표준 방법**
    - 모든 HTML 요소는 HTMLElement라는 공통된 기능을 상속받으며 여기에는 data-* 속성을 편리하게 다룰 수 있는 dataset이라는 속성이 포함되어있음.

### data-* 속성이 등장한 배경

- **data-* 속성이 없던 시절(제이쿼리 활용)**에는 어떻게 HTML ↔ JS 사이에서 데이터를 주고 받았는지?
    - 제이쿼리의 `.data()` 메서드
    - HTML 요소의 속성이 아니라 **제이쿼리 내부 데이터 캐시에 데이터를 저장**하는 방식.
        
        → **돔에 데이터가 직접 남지 않아** HTML만 보고는 어떤 데이터가 저장되어 있는지 알기 어려움.
        
- 반면 **SSR 환경**에서는 클라이언트로 데이터를 전달하기 위한 표준 방식으로 data-* 속성이 널리 사용.
    - SSR: 서버가 완성된 HTML 페이지를 클라이언트로 보냄.
    - 아이템이 고유한 데이터를 포함해야만 클라이언트쪽 자바스크립트가 이어서 작업을 수행할 수 있음.
        
        → 이 데이터를 전달하는 가장 이상적인 표준 통로.
        
- 즉, 데이터 저장의 역할을 명확히 분리하고 표준화하는 역할
    - id나 class 같은 다른 속성에 id=”user-123”이나 class=”item-info-456”처럼 데이터를 억지로 넣으면 실수로 민감한 정보가 노출될 가능성 있음.

### data-* 속성 사용법

- HTML에서
    
    ```html
    <div id="user-profile" **data-user-id**="123" data-user-role="admin">
    	홍길동
    </div>
    ```
    
    - **케밥 케이스**로 작성 → **자바스크립트에서 함께 사용할 수 있는 데이터**로 저장됨.
- 자바스크립트에서
    
    ```html
    const id = profile.dataset.userId; // "123"
    profile.dataset.userRole = "editor"; // 역할 변경
    ```
    
    - **카멜 케이스**로 작성 → dataset이라는 속성을 사용해서 데이터에 접근할 수 있음.
