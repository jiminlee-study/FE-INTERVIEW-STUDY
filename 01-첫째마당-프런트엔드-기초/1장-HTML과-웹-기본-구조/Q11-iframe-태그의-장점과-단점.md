# Q11. iframe 태그의 장점과 단점은 무엇인가요?

### `<iframe>` 태그의 의미와 사용법

- `<iframe>`: HTML 문서 안에 **또 다른 독립적인 HTML 문서를 삽입**하는 태그.
    - 웹 사이트 안에 또 하나의 작은 웹 브라우저 창을 여는 것과 같음.
    
    ```html
    <iframe
    	src="https://www.youtube.com/embed/your-video-id"
    	width="560"
    	height="315"
    	title="임베드된 유튜브 영상"
    >
    </iframe>
    ```
    

### <embed>, <object> 태그와 차이점

- `<embed>`, `<object>` 모두 **웹에서 외부 콘텐츠를 포함**하기 위한 방식
- `<embed>`: 플래시나 PDF 뷰어 같은 웹 브라우저 플러그인 기반의 콘텐츠를 삽입하는 데 주로 사용되었음.
    
    → 표준성, 확장성 면에서 한계
    
- `<object>`: <embed> 보다 널리 사용됨. 이미지, 오디오, 비디오, PDF, 다른 HTML 문서 등 다양한 종류의 외부 객체 삽입할 수 있음.
    
    → 단순히 다른 웹 문서를 삽입하는 것이 목적이라면 <iframe>보다 사용법이 복잡.
    

### <iframe> 태그의 장점과 단점

- 장점
    - **간편한** 외부 콘텐츠 삽입
    - **비동기 로딩**: `<iframe>` 태그의 **내부 콘텐츠는 부모 페이지와 별도로 불러오므로** `<iframe>` 태그의 로딩이 느려도 부모 페이지의 렌더링을 막지 않아 초기 로딩 성능에 유리.
    - **보안 격리**: 동일 출처 정책(SOP)에 따라 `<iframe>` 태그의 내부 문서와 부모 문서는 서로의 돔에 직접 접근 불가.
- 단점
    - 성능 저하: 돔이나 window 객체 같은 **독립적인 브라우저 컨텍스트를 각각 생성**
        
        → 메모리, CPU 자원 상당히 소모
        
    - SEO 어려움: 검색 엔진이 `<iframe>` 태그의 내부 콘텐츠를 부모 페이지와 분리된 콘텐츠로 인식
    - 보안 취약점: 클릭재킹 공격에서 매개체로 악용될 수 있음.
        - 신뢰할 수 있는 콘텐츠에만 사용해야 함.
        - **X-Frame-Options**나 **CSP**(`<iframe>` 삽입을 허용할 출처를 더 세밀하게 지정할 수 있는 최신 방식) 같은 보안 설정 반드시 적용해야 함.
