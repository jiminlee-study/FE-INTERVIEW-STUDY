# Q38. 얕은 복사와 깊은 복사란 무엇인가요?

- 프로그래밍에서의 데이터 복사: 원본 데이터와 동일한 내용의 새로운 데이터를 만드는 것.
- 자바스크립트에서의 데이터 복사: 데이터의 종류가 **원시 타입이냐 참조 타입이냐에 따라 미묘하게 달라짐.**

### 원시 타입과 참조 타입의 복사 차이

- 변수에 **원시 타입(숫자, 문자열, 불리언 등)을 할당**할 때: **값이 직접 복사**됨.
    
    ```jsx
    let num1 = 10;
    let num2 = num1; // num1의 값 10이 num2에 그대로 복사됨.
    num2 = 20;
    console.log(num1); // 10(num2를 변경해도 num1은 영향 받지 않음.)
    ```
    
- 변수에 **참조 타입(객체, 배열 등)을 복사할 때**
    
    ```jsx
    let person = {
    	name: 'Tom'
    }
    
    let newPerson = person;
    console.log(newPerson.name); // Tom
    
    newPerson.name = 'Jane';
    console.log(person.name); // Jane
    ```
    
    - newPerson의 name을 변경하면 **기존 person 객체의 이름까지 함께 변경**된다는 문제가 있다.
    - 이유: 객체의 경우 **값을 공유**하기 때문.
        
        → 이 문제를 해결하기 위해 얕은 복사와 깊은 복사라는 개념이 등장한다.
        

### 얕은 복사

- **얕은 복사(shallow copy)**: 객체(또는 배열)를 복사할 때 **가장 상위 레벨의 값만 복사**하는 방식.
    - **원본 객체 내부에 있는 중첩된 객체나 배열**은 새로운 메모리 공간에 복사되지 않고 원본의 참조, 즉 **메모리 주소를 그대로 공유**함.
    
    ```jsx
    const originalObject = {
    	name: '김철수',
    	age: 25,
    	address: {
    		city: '서울',
    		zip: '12345',
    	}
    };
    
    const shallowCopy = { ...originalObject }; // 스프레드 문법을 이용한 얕은 복사
    
    console.log(shallowCopy);
    // { name: '김철수', age: 25, address: { city: '서울', zip: '12345' } }
    
    // 얕은 복사된 객체의 **1단계 속성** 변경
    shallowCopy.age = 30;
    console.log(originalObject.age); // 25(원본 영향 X)
    console.log(shallowCopy.age) // 30
    
    // 얕은 복사된 객체의 **중첩된 객체 속성** 변경
    shallowCopy.address.city = '부산';
    console.log(originalObject.address.city); // 부산(원본 영향 O)
    console.log(shallowCopy.city); // 부산
    ```
    
    - address 속성은 **객체이기 때문에** shallowCopy.address는 originalObject.address가 참조하고 있는 **동일한 메모리 주소를 참조하기 때문.**
    - 얕은 복사는 객체의 최상위 속성만 복사하고, 중첩된 객체나 배열은 참조를 그대로 공유하는 방식.
        
        → 깊은 복사에 비해 처리 속도가 빠르다.
        
        → 구조가 단순한 객체나 배열을 복사할 때 빠르고 편리.
        
- **깊은 복사(deep copy)**: 객체 또는 배열을 복사할 때 **내부에 있는 모든 중첩된 객체와 배열까지도 모두 새로운 메모리 공간에 재귀적으로 복사**하는 방식.
    - 원본 객체와 복사된 객체는 와전히 독립적이므로 한 쪽도 변경해도 다른 쪽에 영향을 전혀 주지 않음.
    - `JSON.parse(JSON.stringify(object))`를 이용 → **메모리 공간에 완전히 독립적인 객체가 생성**됨.
        - `JSON.stringify()`: 자바스크립트 객체를 JSON 문자열로 변환
        - `JSON.parse()`: JSON 문자열을 다시 자바스크립트 객체로 변환
    
    ```jsx
    const originalData = {
    	name: '김철수',
    	scores: {
    		math: 90,
    		english: 85
    	},
    	hobbies: ['독서', '운동'],
    	graduationDate: new Date()
    };
    
    const deepCopy = JSON.parse(JSON.stringify(originalData));
    
    console.log(deepCopy);
    /*
    {
    	name: '김철수',
    	scores: { math: 90, english: 85 },
    	hobbies: ['독서', '운동'],
    	graduationDate: '2025-06-12T01:52:59.000Z' // Date 객체가 문자열로 변환됨.
    }
    */
    
    // 깊은 복사된 객체의 중첩된 속성 변경
    deepCopy.scores.math = 95;
    deepCopy.hobbies.push('요리');
    deepCopy.graduationDate.setYullYear(2026); // 오려 발생 가능
    
    console.log(originalData.scores.math); // 90(원본 영향 X)
    console.log(deepCopy.scores.math); // 95
    
    console.log(originalData.hobbies); // '독서', '운동'
    console.log(deepCopy.hobbies); // ['독서', '운동', '요리']
    
    console.log(originalData.graduationDate); // Date 객체
    console.log(deepCopy.graduationDate); // 문자열
    ```
    
    - 원본 데이터를 그대로 유지하면서 복사본을 자유롭게 수정해야 할 때
    - 중첩된 객체가 많거나 데이터의 무결성이 중요한 경우
        
        ex) 리덕스 상태 관리에서 상태 불변성을 유지할 때
        

### 깊은 복사의 한계와 극복 방법

- JSON 방식의 한계
    1. Date 객체는 JSON 문자열로 변환될 때 **ISO 형식의 문자열로 변환**됨.
        - 다시 JSON.parse()를 호출해도 문자열이 Date 객체로 복원되지 않고 그냥 문자열로 남아 있음.
        - **Date 객체의 메서드를 사용할 수 없게 됨.**
    2. 객체 **내부에 함수가 포함**되어 있는 경우
        - JSON.stringify() 과정에서 **함수가 제거**됨.
        - JSON은 **데이터 포맷**이므로 **실행 가능한 코드를 포함하지 않음.**
    3. 속성값이 undefined의 경우 
        - JSON.stringify() 과정에서 해당 속성 자체가 제거됨.
    4. 순환 참조가 있는 객체의 경우
        - 변환 과정에서 오류 발생.
    5. Map, Set, RegExp 등 내장 객체
        - JSON.parse(JSON.stringify())를 거치면 원래 타입으로 복원되지 않고 일반 객체나 빈 객체가 되거나 사라짐.
- 안전한 깊은 복사 방법
    1. 재귀 함수를 이용한 구현
        - 재귀 함수로 **객체의 모든 중첩된 속성을 순회하며 복사**하는 방법.
        - 가장 유연하게 원하는 방식으로 구현할 수 있으나 코드 복잡 + 예외 처리 신경써야함.
    2. 외부 라이브러리를 사용
        - Lodash의 `_.cloneDeep()`
    3. 최신 브라우저에서 제공하는 structuredClone() API 사용
